# 24 · P1「全下」逐项回填 + 下载中反馈

票 23 验收中发现：关闭自动下载后点「本篇资源全下」，要等 `Promise.all` 里**全部**资源 settle 才回填一次，期间零反馈；任一资源慢（大图/PDF）或请求挂起都会拖住整批，用户以为没反应，退出重进才看到已下载的资源。单张下载不依赖整批刷新，所以一直正常。

**完成定义**：

- 点「全下」后，每个资源落地（成功或失败）就触发一次防抖回填（300ms），不等最慢的。
- 下载期间按钮显示「下载中…」并禁用；全部 settle 后恢复「全下」。
- 结束兜底刷新一次，保证最后一批一定显示。
- 失败项保持「未下载」可再点重试（本次不改「未镜像」语义）。
- 测试：App 集成（两个资源、一个 fetch 挂起：断言快的先回填、慢的仍「未下载」、按钮「下载中…」；放行后慢的回填、按钮复原）；票 23 既有集成测试保持绿。
- `npm test` / `npm run typecheck` / `npm run verify:pwa` 全绿；隐私自查（哑值 fixture）。

## 决策

- 回填仍走现有 `refreshToken` → ReaderView 重装配（读 IDB 缓存），不新增命令式 DOM 通道。
- 防抖 300ms：避免多个资源同时落地时连续重建 shadow（开了 Mermaid 时尤其重要）。
- 切走笔记即作废旧批次的进度状态（旧批次继续下载，但不再影响新笔记的按钮/回填）。
- 不做：请求级超时、失败标「未镜像」（留后续票）。

## Answer

2026-11-23 完成。
